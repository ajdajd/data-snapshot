# Schema v1.2 Representation Stress Test Report

**Status:** Superseded as Schema Validation Exercise 3

**Decision date:** September 8, 2026

## Decision

This exercise is retained as an exploratory **Schema v1.2 Representation
Stress Test**. It must not be reported as Schema Validation Exercise 3 or used
as the confirmatory comparison with Validation 2.

The intended Validation 3 design changed only the evaluated schema from
v1.1.1 to v1.2, together with the unavoidable change from a Markdown schema to
generated JSON Schema. The executed instrument also broadened the measured
construct. It explicitly invited candidates concerning relationships, nesting,
cardinality, normalization, constraints, and definitions, and it removed
Validation 2's requirement to express each candidate as a proposed reusable
field. The resulting candidate counts are therefore not comparable with
Validation 2 as evidence of a change in schema coverage.

## Preserved evidence

The archive preserves the original protocol, execution notebook, analysis
notebook, prompts, configuration, runner implementation, tests, calibration
outputs, and full-run outputs without maintaining them as an active package.
Internal references retain their historical `schema_validation3` names so the
files remain an exact record of the executed instrument.

The completed run passed its technical execution checks:

- 202 successful results for the same 202 filenames used in Validation 2;
- no duplicate results, corpus mismatch, malformed output, or unresolved error;
- GPT-5.5 with medium reasoning, Flex processing, and the complete generated
  v1.2 schema; and
- estimated full-run token cost of $8.809742.

The model returned 129 `no_critical_gap_found`, 47 `possible_gap`, and 26
`critical_gap_found` assessments. It surfaced 90 candidates across 73
snapshots. A preliminary analyst grouping assigned 54 rows to relational
representation themes: 26 panel or component associations, 16 deeper
hierarchies, and 12 other scoped relationships. The other 36 rows were judged
covered, outside the established scope, operational, document-level, or
insufficiently supported. No candidate was judged to require a new metadata
field.

## Interpretation boundary

These results may support future exploratory work on the limits of v1.2's
relational representation. They do not show that v1.2 misses more metadata
fields than v1.1.1, that the Pydantic implementation caused a regression, or
that the Validation 2 and stress-test candidate counts measure the same thing.

The corrected Validation 3 must reuse the Validation 2 prompt and candidate
contract, including the proposed-field requirement. Its only response-contract
adaptation is that closest existing locations are reported as exact v1.2 schema
paths so nested Pydantic fields can be referenced accurately.
